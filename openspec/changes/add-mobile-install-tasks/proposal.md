## Why

Today the only way to get floppy onto a phone is `mise run dev:android` / `dev:ios`, which
tethers the app to the Vite dev server on the Mac. There is no one-command way to build a
standalone, signed app and put it on a connected Android or iOS device so it keeps working
after the cable comes out. The build-only tasks stop at an artifact, and on Android that
artifact is an unsigned release APK that `adb install` refuses.

## What Changes

- Add `install:android`: build a signed release APK for the connected device's ABI and
  install it with `adb`. Falls back to the debug variant on `--debug`.
- Add `install:ios`: build a signed IPA with the `debugging` export method and install it
  on the connected iPhone with `xcrun devicectl`.
- Give Android release builds a signing config that reads the gitignored
  `src-tauri/gen/android/keystore.properties`, following the Tauri signing guide.
- Add `keystore:android` (or an automatic first-run step) that generates a local
  development keystore and writes `keystore.properties`, so release builds sign
  without manual setup.
- Extend the doctor script to check the pieces these tasks need: `keytool`, `adb`,
  `xcrun devicectl`, and a usable keystore.

## Capabilities

### New Capabilities

- `device-install`: building and installing a standalone floppy build on a connected
  Android or iOS device from one developer task, including local release signing.

## Impact

- `mise.toml`: three new tasks under `# --- install ---`.
- `scripts/`: a small install helper per platform, or inline task bodies.
- `src-tauri/gen/android/app/build.gradle.kts`: `signingConfigs.release` wired into
  `buildTypes.release`. This file is generated by Tauri but is checked in, so the edit
  persists.
- `scripts/doctor-macos.sh` and `scripts/doctor-linux.sh`: new checks. iOS install is
  macOS-only.
- No app code, IPC, or runtime behavior changes. Nothing new is committed that carries a
  secret: `keystore.properties` is already in `src-tauri/gen/android/.gitignore`.
